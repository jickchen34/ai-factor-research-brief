# 代表性项目与基准

以下调研关注各项目如何组织研究、使用反馈和验证候选。论文中的效果受数据、市场、成本和实验预算限制，不代表同样方法在其他条件下有效。

| 项目 | 做法 | 对研究控制的启发 |
|---|---|---|
| [RD-Agent(Q)](https://github.com/microsoft/RD-Agent) | 把研究提案、开发、回测和反馈放在同一流程中，协调因子和模型优化。 | 要能记录哪类动作消耗了预算、反馈来自哪里，以及何时应切换研究方向。 |
| [QuantaAlpha](https://github.com/QuantaAlpha/QuantaAlpha) | 对包括假设、表示和实现的研究轨迹进行进化，不只修改最终候选。 | 保留推导过程和父子关系，才能解释一次修订为什么有效或失败。 |
| [Alpha-GPT](https://arxiv.org/html/2308.00016v1) | 把人的研究意图转化成可校验候选，结合交互与程序化搜索。 | 人可以提供假设或纠正方向。人工干预也应留痕，而不是被当成未记录的外部先验。 |
| [AlphaAgent](https://arxiv.org/html/2502.16789v2) | 将假设一致性、结构新颖度和复杂度用于约束搜索。 | 提高搜索产量的同时仍要检查重复和复杂度。语义一致性不能替代实证评价。 |
| [AlphaGen](https://arxiv.org/pdf/2306.12964v1) 与 [HARLA](https://journal.hep.com.cn/fcs/EN/10.1007/s11704-025-41061-5) | AlphaGen 以因子组合的增量为目标。HARLA 将语言模型提案与强化学习结合。 | 区分提案机制和评价目标。比较候选时，可看它加入已有集合后的边际贡献，而非只比较单个成绩。 |
| [AlphaBench](https://proceedings.iclr.cc/paper_files/paper/2026/file/4f3820576130a8f796ddbf204c841487-Paper-Conference.pdf) | 分开评价生成、评价和搜索能力。 | 会生成不等于会评价。在相同预算下比较不同方法，并分别记录各环节的能力。 |
| [AlphaQT-Bench](https://aclanthology.org/2026.findings-acl.138.pdf) | 区分金融代码的可执行性、时间因果性、功能正确性与结构质量。 | 能运行不代表金融含义正确，也不代表没有未来信息。不同失败需要不同的处置。 |

这些项目适合用来比较控制流程的取舍。一个项目在给定预算或任务上的结果，不构成把它的技术栈、数据或角色分工搬入其他系统的理由。
